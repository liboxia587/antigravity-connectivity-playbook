# 连通性与分层诊断指南

本指南提供针对 AGY 编程工具链的系统化排查路径。核心准则为：**依据具体错误体与响应载荷诊断，严禁仅凭 HTTP 状态码盲目切线**。

---

## 一、排查总则

```text
客户端请求发起
  │
  ├── [传输层/本地层] 端口监听？TCP握手？TLS建立？
  │     └── 失败：排查本地代理进程、端口冲突、显式代理配置
  │
  ├── [网关/端点层] HTTP 状态码返回
  │     ├── 401 Unauthorized：确认响应来自哪个端点，再依据错误体检查认证；不自动切线
  │     ├── 429 Too Many Requests -> 结合错误体检查限流、配额与请求来源；不自动切线
  │     ├── 5xx Server Error：服务端故障或网关异常 -> 稍后重试
  │     └── 400 Bad Request：必须深入检查 JSON 错误体
  │
  └── [错误体判定]
        ├── 明确包含 "User location is not supported" -> 当次请求受到地区策略拒绝；仅 FAILED_PRECONDITION 不足以分类
        └── 包含参数格式/Schema错误 -> 客户端请求参数不合法，与网络无关
```

---

## 二、分层排障细节

### 1. 传输层与基础网络（TCP / TLS / 本地代理）
- **本地监听有效 ≠ 上游连通**：代理工具本地端口显示 `LISTENING` 仅代表本地进程在监听，不代表数据能够成功出境并抵达模型端点。
- **透明中继与显式代理**：在 Windows 环境中，完全依赖透明中继可能因规则或路由注入问题出现高延迟甚至超时（曾观察到 35 秒超时现象）；显式配置 HTTP/SOCKS5 代理端口能提供更具确定性的流量走向。
- **TLS 握手终止（EOF / Reset）**：多发生在客户端与中继或上游网关之间，需排查本地防火墙、系统代理环境变量或通道连接性。

### 2. HTTP 状态码与响应体深度解析
- **地区限制（必须依据具体错误体）**：
  - 只有当 HTTP 400 返回的 JSON 体中明确包含错误字段（如 `FAILED_PRECONDITION` 以及 `User location is not supported`）时，才能确认当前出境节点被服务端判定为不在支持服务区域内。
  - 严禁把所有 HTTP 400 笼统视作地区问题。参数缺失、模型名称弃用同样会返回 400。
- **认证失效（401 / 403）**：
  - 收到 401 只说明某个 HTTP 服务返回了响应；先核实响应目标及是否经过中间网关，再结合错误体判断认证问题，不能据此确认完整网络链路或账号状态。
  - 若确认是认证问题，由用户本人检查登录状态或完成认证，不把切线作为默认处理。
- **配额耗尽与并发超限（429 / RESOURCE_EXHAUSTED）**：
  - 返回 429 或含有配额超限描述时，表明请求已达服务端，但当前账户配额或速率上限被触发。
  - **长上下文放大效应**：即使在交互界面仅输入“Hi”或单行测试 Prompt，客户端可能附带上下文；本案例回执单次约 1.17 万 total_tokens，具体组成未核实，不能外推其他工具或请求的消耗。请结合实际 Token 消耗核对服务商配额面板。
- **超时（Timeout）**：
  - 区分本地连接超时（代理未响应）与上游响应超时（服务端负载高或模型生成过长）。设置明确的有界超时时间，避免任务无限挂起。

### 3. 组件层级差异
- **网页能打开 ≠ API 可用**：网页端与 API/CLI 接口的访问入口、鉴权机制及地区路由策略可能不同。
- **CLI 成功 ≠ 桌面端可用**：CLI 命令行与图形化桌面 IDE 可能使用不同的环境配置、网络调用库或内置代理设置。本案例先验证 CLI，再单独验证桌面端；二者成功不能互相替代，也不要求所有桌面场景必须先用 CLI。

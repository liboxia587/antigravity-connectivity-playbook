# 受控恢复与切换原则

在连通性出现故障时，盲目尝试各种切换往往会导致环境陷入混乱。本手册规范了在排障与恢复过程中的控制边界。

---

## 一、核心原则

1. **主线正常绝不切换**：只要当前通道工作正常，不主动进行任何网络变更。
2. **严格隔离验证**：测试候选通道时，必须通过独立配置或独立端口进行，不得覆盖正在使用的生产配置。
3. **真实模型最小请求验收**：候选通道的可用性必须通过向真实模型端点发起一次受控的最小 CLI 请求进行验收，以实际返回码和返回体为准。
4. **禁止盲目自动切换**：自动化脚本若无法准确识别认证失败、配额枯竭或服务端整体宕机，盲目轮询可能增加请求量、成本与故障排查难度。
5. **始终保留回退路径**：动改任何本地配置前，必须留存原文件备份；一旦候选通道验证不符预期，立即无条件回退。

---

## 二、受控恢复标准化步骤

### 步骤 1：现状留存与错误分类
- 记录当前故障的精准现象与错误返回体。
- 依照 [诊断指南](diagnosis.md) 排查：错误体是否支持认证异常或配额/限流判断（不能只看401或429）？
- 若属于凭证或额度问题，停止切线，走账户维护流程。

### 步骤 2：建立隔离测试通道
- 为备选通道分配独立的本地监听端口，避免与主服务端口冲突。
- 启动备选通道，确认本地端口就绪。

### 步骤 3：最小 CLI 真实调用检验
- 使用独立端口向大模型后端发起一次最简 CLI 探针调用。
- 检查指标：
  - 进程退出码是否为 0。
  - 响应内容是否为正常的模型生成结果。
  - 耗时是否在可接受的有界范围内。
- 若返回地区拒绝（`User location is not supported`）或网络错误，立即标记该候选为不可用并退出。

### 步骤 4：桌面端人工受控接入与观察
- 在 CLI 探针调用成功后，评估是否将桌面端配置指向该经验证的独立端口。
- 进行单次实际代码补全或问答交互测试。
- 当操作记录显示桌面端回复正常，确认当次恢复完成。

### 步骤 5：记录与回退预案
- 记录切换时间与通道特征（如代号“候选 A”）。
- 若桌面端调用异常，立即还原先前的配置文件。

操作前保存工作；正常退出相关应用后再改变其启动环境，不强杀未知进程。独立入口仍可能共享供应商与底层网络。仅在合法授权和服务允许范围内验证，不以切线规避账号或服务资格限制。本仓库没有部署工具，步骤是原则，需参考对应组件的官方说明。

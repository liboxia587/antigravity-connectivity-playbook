# 案例复盘：2026-10-08 连通性排查与恢复实录

本案例记录了 2026-10-08 在单台 Windows 工作机上遇到 AGY 连通性异常时的一次排查与受控恢复过程的有限记录。

---

## 一、事件背景

- **时间**：2026-10-08
- **现象**：原有主通道出现连接异常（观察到持续超时与连接中断），导致桌面端 AI 辅助编程环境无法正常工作。
- **目标**：在不破坏其他日常办公应用网络的前提下，排查并为 AGY 恢复可靠的模型后端连通性。

---

## 二、排查与验证过程

### 阶段 1：网络现状检查
- 对原通道进行检查，发现上游连接存在持续握手失败与超时。
- 对其他应用目标收到 HTTP 401，仅记录为一次响应可达，未完成其他应用全功能验证，决定保持其他应用设置不变，为 AGY 搭建隔离的测试通道。

### 阶段 2：候选通道的隔离实测（脱敏代号记录）

为避免相互影响，排查时为各候选通道配置独立的本地代理监听端口，并发起真实 CLI 请求（次数如下）：

1. **候选 A**：
   - 方式：通过专属独立端口发起 CLI 探针请求。
   - 结果：CLI 连续两次真实调用均返回成功（进程退出码 0，耗时约 3.2 ~ 3.6 秒）。
   - 桌面端验证：随后在桌面端 IDE 中进行实际对话交互，当时操作记录显示桌面端成功返回有效模型回复。
   - 判定：作为当次恢复通道启用。

2. **候选 B**：
   - 方式：通过另一独立端口发起单次 CLI 探针请求。
   - 结果：CLI 返回成功（进程退出码 0，耗时约 4.4 秒）。
   - 桌面端验证：当时未继续进行桌面端配置与实测。
   - 判定：记录为“单次 CLI 测试成功”，未列入已全面交付通道。

3. **候选 C**：
   - 方式：通过独立端口发起真实 CLI 模型请求。
   - 结果：返回码非 0（退出码 3），响应体中明确包含 `FAILED_PRECONDITION` 以及 `User location is not supported`。
   - 判定：真实请求被地区策略拒绝。立即将该候选排除，不再做任何多余尝试。

---

## 三、经验与教训

1. **真实模型响应是唯一有效标准**：仅靠本地 TCP 端口监听成功、甚至是 HTTPS 握手成功，均不能证明通道可用。候选 C 证明了只有真实携带模型请求，才能验证地区策略与端点准入。
2. **显式代理比盲目透明中继更可控**：在 Windows 环境排障中，为工具显式指定代理端口，本次显式路径成功、仅中继测试35秒超时；超时原因尚未确定，不能推广为显式代理必定解决问题。
3. **候选表现具有时效性**：候选 C 的失败仅代表其对应出境节点在 2026-10-08 当次测试时被服务端拒绝，不可推论为该地区全量或长期的策略行为；同样，候选 A 的成功亦不代表未来能永久可用。
